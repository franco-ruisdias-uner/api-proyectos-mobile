Decisiones tomadas:
- C1–C6: comunes, ya cerradas.
- P1 (PROVISORIA, autónomo): `PATCH /yo` con `nombre` o `avisosActivos` en `null` → 400
  `VALIDACION_FALLIDA`; `telefono: null` lo borra.
- P2 (PROVISORIA, autónomo): rango fuera del archivo → 416 `RANGO_NO_SATISFACIBLE` con
  `Content-Range: bytes */<total>` (código agregado al catálogo).

Correcciones de este intento (por el `verificador-contrato`, tres pasadas hasta verde):
- `PATCH /yo` con `nombre: null` o `avisosActivos: null` daba 500 (restricción NOT NULL de la
  base): ahora 400. Nuevo decorador `Opcional()` en `src/common/validacion/`.
- Un campo con el tipo equivocado (teléfono numérico) decía "El teléfono es demasiado largo.":
  ahora "Revisá el teléfono: no tiene el formato correcto.".
- `Authorization: Bearer <t> <t>` se aceptaba: ahora tiene que ser exactamente
  `Bearer <token>` (el esquema no distingue mayúsculas, como dice la RFC 7235).
- ECONNRESET / respuestas ajenas intermitentes en la matriz con MySQL y MariaDB: el arnés e2e
  abría un servidor efímero por pedido; ahora escucha en un puerto fijo por archivo. Dos
  matrices completas seguidas en verde después del cambio.
- README para alumnos (sección 13), con la tabla de errores controlada contra el catálogo por
  un test unitario; `CHANGELOG.md`.
